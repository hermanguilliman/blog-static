Эпизод 1. Утечка сертификатов#

В Telegram появился пересланный пост об утечке сертификата центра сертификации eMudhra:

THIS IS NOT A DRILL: CA certificate leaked. Update everything.

https://emudhra.we-have-a-problem.com/

Источник: https://t.me/lina_shitpost/3634

После появления этой информации возник вопрос о наличии сертификатов Яндекса в доверенных корневых центрах сертификации и возможности создания собственного бэкенда для Quasar.

Эпизод 2. Утечка приватных ключей#

Позже появилась информация об утечке приватных ключей:

https://chaos.social/@fluepke/117474156947559280

Автор использовал репозиторий с сертификатами для необходимых поддоменов Яндекса и начал разработку собственного API для управления устройством без зависимости от официального бэкенда.

В ходе работы исследовался протокол uni.ws, определения которого распределены по множеству файлов .proto. При анализе также изучались декомпилированный код и конфигурация устройства.

Эпизод 3. Активация ADB через серверную конфигурацию#

В процессе анализа выяснилось, что настройки ADB можно переопределить с помощью серверной конфигурации.

Для этого была реализована следующая функция на Rust:

pub(super) async fn get_sync_info() -> Json<serde_json::Value> {
    Json(serde_json::json!({
        "status": "ok",
        "config": {
            "account_config": { "spotter": "alisa" },
            "device_config": { "name": "quasar" },
            "system_config": {
                "adbd": { "remoteActivation": true, "network": true }
            }
        },
        "subscription": { "mode": "transaction" }
    }))
}

После перезагрузки станция получила конфигурацию от бэкенда.

Итог#

В результате эксперимента автор получил сетевой доступ к ADB и root-оболочке Яндекс Станции Мини 2. Ключевым этапом стало обнаружение возможности изменять настройки ADB через серверную конфигурацию устройства.
